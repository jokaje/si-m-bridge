# SI-M connector protocol v1 (candidate, not deployed)

Source of truth: this standalone service's SQLite database. Hermes plugin only produces explicit events; no Telegram-final-response mirroring. API endpoints are under `/v1`; JSON UTF-8; unrecognized versions rejected. Each paired device is bound to exactly one owner/profile (`agent`) chosen by the operator, not supplied by a device request. K-AI/default and other profiles must use separate configured instances/data stores; a profile name is a routing label, NOT an OS isolation boundary. No Hermes master key is sent to a device.

## Pairing

Operator runs `si-m-bridge --db PATH pair --profile NAME --owner NAME --device NAME --base-url https://...` (loopback HTTP permitted). CLI creates 32-byte random one-use secret, stores only SHA-256 domain-separated digest in SQLite, expiry 120 seconds, prints `sim://pair?v=1&url=...&code=...` for QR encoding locally. Client sends `{version:1,code,device,profile}` to `POST /v1/pair/confirm`; profile/device must equal operator-authorized values, expiry strictly greater than server time. `BEGIN IMMEDIATE` serializes consumption; only one claimant gets a 32-byte random device bearer token. Persist digest, not token; failed/mismatched claims do not consume code. Pair URL must be HTTPS or loopback HTTP; never send credentials to LAN plaintext or redirect. QR and response are sensitive; do not log them. Device revoke via CLI makes token immediately unusable. QR alone is possession-based authorization; verify the profile/device shown on client against the operator's QR before confirmation. Do not publish a QR image automatically.

## Device HTTP

`Authorization: Bearer <device-token>`, `Cache-Control: no-store`. Inbox responses are small; HTTP POST bodies are limited to 90 KiB (raw firmware PCM up to 256 KiB). `GET /v1/inbox/meta` returns `{version:1,unread,cursor,binding}` without content; `GET /v1/inbox?cursor=N&limit=1..50` returns `{version:1,items:[{id,kind,title,body,created,opened,openedAt}],cursor,binding}` in ascending durable sequence. Cursor is the last returned sequence, or input if empty; expired records are skipped. GET never ACKs. `POST /v1/inbox/{id}/open` opens only the authenticated scope; duplicate ACK returns success, foreign/expired IDs neutral 404. Wake fetch does not count as open. `task_done` and `question` only; proactive is off. No acoustic command/content is sent while display off; firmware applies quiet 22:00–07:00 and unknown-time silence, one soft local tone with bundling, never wake display or microphone. Device/app implementation follows separately.

`POST /v1/turn-stream` accepts authenticated `{version:1,pcm16le_b64,sample_rate:16000}` (mono PCM signed little-endian, at most 64 KiB decoded) **or** the firmware's raw `Content-Type: application/vnd.kim.pcm;rate=16000;channels=1;format=s16le` (up to 256000 bytes). Empty or odd-length input is rejected. Both forms return `Content-Type: application/vnd.kim.stream-v1` with HTTP transfer coding determined by the server/proxy: `M` with one-byte payload `01`, then 1..16 `A` frames with nonempty even-length 16-kHz mono s16le PCM (max 256000 bytes/frame, 1280000 total), then zero-length `E` and EOF. Every header is ASCII type plus little-endian uint32 length. On failed STT/Hermes/TTS before output, HTTP 503 (not a success frame); no `A` frame is emitted unless synthesis completed. A client must discard audio on premature EOF/cancellation. No transcript/reply text is sent in this binary response. The frame payload contract is independent of HTTP/1.1 transfer coding. The audited firmware parser rejected both `Content-Length` and `Transfer-Encoding`; therefore current Uvicorn chunked output is not device-compatible until the firmware parser is repaired and tested. Disabling nginx chunking is not a verified cure. No physical device playback has been tested.

STT requires an explicitly configured existing local Whisper model or command adapter; TTS requires an existing local WAV speech endpoint or command adapter. No implicit model download/install and no paid provider selection. Text path `POST /v1/turn` accepts `{version:1,text}` and calls Hermes directly. Server-generated stable session IDs are stored by owner/profile/device in SQLite and passed in `X-Hermes-Session-Id` and `X-Hermes-Session-Key`; device cannot select or read another session. This is not Telegram history. API upstream must be loopback HTTP or verified HTTPS, configured with a separate server-side Hermes API secret, never the device token. HTTPS redirects disabled. A dedicated Hermes home/profile and API key are prerequisites for real isolation; a profile label alone is not a security boundary.

## Producer

Plugin tool `sim_notify` takes explicit `event_id`, `kind`, `title`, `body`, `owner`, `profile` and writes into the connector DB. Operator configures EXACT owner/profile via environment; mismatches rejected. Plugin additionally requires `SIM_CONNECTOR_HERMES_HOME` to resolve to the exact active `HERMES_HOME`; missing or mismatched homes fail closed. This protects an accidentally loaded plugin in another profile, not against a process with permission to change its own environment. Stable event ID retries are idempotent, first payload wins. Only explicitly invoked tool writes; no global response hook. Producer cannot turn an arbitrary Telegram final response into a task completion. No automatic real-family messages or sound probes.

Security: bounded identifiers/text, parameterized SQL, secure local DB permissions, no tokens in logs, no public bind default (`127.0.0.1`), no CORS; external deployment needs a reviewed HTTPS reverse proxy with device reachability. Retention: expires 30 days after insert; expired messages ignored, purge operator-controlled. Revocation does not erase inbox. Network disconnection does not ACK. No claim of live Hermes gateway integration until isolated runtime call is exercised.

Cursor is canonical decimal text in [0, 9223372036854775807], never a JSON number (no JS/cJSON precision loss). `opened` is a boolean; `openedAt` is an optional timestamp (`null` while unread). `binding` is an opaque 32-hex generation identifier assigned by the server on each pairing, never derived from bearer plaintext. The device compares binding on each metadata/page response and resets RAM and persisted acoustic cursor on change; pagination only continues for the same binding. Existing installations without a binding are invalidated and must pair again.
